# invox audit: streams, interactivity/safety, configuration

## (a) Verdict
invox has a single output contract. Every command prints human sentences to stdout, there is no TTY detection, header, escaping or `--json`, and child processes (tectonic, the login shell, vim) write straight into stdout. For a single-user tool, its writes are better than average: temp file + rename, `new`/`archive`/`archive edit` refuse to overwrite, and yaml.v3 keeps comments. But `email` deletes files the user named with `-o`, `-e` and `config` start vim with no TTY and can hang, and `init` silently hides an existing legacy setup. Configuration has no `INVOX_CONFIG_DIR`/`--config`, no `help environment`, macOS and Windows use different directory schemes, and a broken config.yaml blocks every command, including `init` and explicit `-c`.

## (b) Stream routing (VERIFIED by running)

| command | stdout | stderr | correct? |
|---|---|---|---|
| init | `Initialized <dir>` + `created/exists <file>` ×5 | – | no: status belongs on stderr (or TTY-only) |
| config, customer config | editor output, login-shell profile output, `Opened <path>` | editor stderr | no: `Opened` goes to stderr; profile noise leaks |
| new | `Created X.yaml for CUST (NUM)` | errors | no: should print just the path (last line) |
| new -e | the same, plus vim's screen if there is no TTY | vim warnings | no |
| increment | `Incremented f for C: A -> B` | errors | no: a sentence, not data |
| validate | `Validation OK: … total 120,00 \euro` | errors (mixed prefixes, no line numbers) | partly: LaTeX macro leaks into the terminal |
| render | `Rendered invoice.tex for …` | errors | no: status line |
| build | **tectonic's stdout** + `Built X.pdf …` (+`Archived a -> b`) | tectonic stderr | no: child stdout must go to stderr |
| email | xdg-open/osascript stdout + `Opened email draft …` | errors | no |
| archive | `Archived a -> b` | errors | partly: should print the archive path only |
| archive edit | `Editing <archive> -> <copy>` | errors | partly: should print the working-copy path |
| archive list / customer list / template list | TSV rows; same bytes on TTY and pipe | – | data on stdout: yes. Contract: no |

## (c) Findings

**1. [blocker] `email` deletes files the user named, and overwrites existing .eml files.** Rule: "Destructive actions: confirm…"; the output is "the path of what was created". VERIFIED: `echo precious > keep.eml; invox email X.yaml -o keep.eml` overwrites keep.eml, then 5 s later it is gone. `ps` showed `PPID 1 /bin/sh -c (sleep 5; rm -f "$1") &`, a detached orphan that outlives invox. The default `<input>.eml` is also overwritten without a check, then deleted. The 5 s timer also races the mail client's load. READ: `commands_invoice.go:212` calls cleanup even when `explicitOutputPath` is true. On Windows, `editor.go:84-92` nests `%q` (Go escaping, doubled `\`) inside `cmd /c "…"`, which cmd does not parse; the delete probably never runs. Fix: never delete a `-o` file. Refuse an existing target unless `--force`. Write the throw-away draft to `os.MkdirTemp` and leave it there (or clean up on the next run) instead of using a timer.

**2. [major] Status chatter on stdout; no clean scripting output.** Rule: "stdout = the data… stderr = progress… hints". VERIFIED: `$(invox new CUST-001)` captures `Created CUST-001-001.yaml for CUST-001 (CUST-001-001)`. Fix: `new`, `archive edit` and `render`/`build` print only the absolute created path on stdout. `Created…`, `Opened…`, `Initialized…`, `Incremented…` go to stderr, or are shown only on a TTY. Add `-q`.

**3. [major] Child stdout pollutes stdout.** VERIFIED: a tectonic stub's stdout line appears in `invox build >o`. `service.go:941` sets `cmd.Stdout = os.Stdout`; `editor.go:23,30,72` does the same. The editor runs as `$SHELL -lc`, so `~/.bash_profile` output (`PROFILE-NOISE`) reached stdout. Fix: send child stdout to stderr. Drop `-l`. Run tectonic with `exec.CommandContext` and stdin set to nil.

**4. [major] No TTY/pipe contract.** Rule: "Non-TTY: no header, tab-separated… `\t` `\n` `\\` escaped". VERIFIED: `customer list | cat -A` and the same command under `script -qec` give identical bytes. There is no header on the TTY and no alignment. A customer name containing `\t`/`\n` breaks a record into two lines (`CUST-002^ITab^ICo$` / `Newline Ltd…`). Raw `\e[31m` from YAML is printed unsanitized. An empty `archive list` prints nothing, even on a TTY. There is no color, so NO_COLOR doesn't apply (that is fine). Fix: add IOStreams (`golang.org/x/term`) and a table printer. On a TTY, print a header, padded columns and `No archived invoices`. When piped, keep the current TSV but escape fields. Strip ANSI.

**5. [major] No `--json`.** Proposed (camelCase, `[]` when empty):
- `customer list --json id,name,legalCompanyName,status,email,currency`
- `archive list --json filename,path,customerId,invoiceNumber,issueDate,dueDate,status,total`
- `template list --json name,path,source` (`source` = project|config|legacy)
- `validate --json` → `{"valid":bool,"file":…,"invoiceNumber":…,"customerId":…,"lineItems":n,"total":{"cents":12000,"currency":"EUR"},"errors":[{"file":…,"field":"invoice.number","message":…}]}`. Today errors are a joined string; only some lines carry a file prefix and none carry a line number.
- `new`/`increment`/`archive`/`build --json` → `{"path","customerId","invoiceNumber","oldNumber","issueDate","dueDate","pdfPath","archivePath"}`.

**6. [major] The editor launches with no TTY and can hang.** Rule: "Never hang on stdin… error without a TTY". VERIFIED: with EDITOR/VISUAL unset, `invox new CUST-001 -e </dev/null` runs `vi`. vim's screen escapes land in stdout, the file is created, and the command exits 1. `sleep 8 | invox new CUST-001 -e` is still blocked at 5 s (timeout 124). `invox config </dev/null` → `exit status 1` (not actionable). Fix: check stdin/stdout TTYs before `openTextFile`. Otherwise return `--edit requires a terminal; open <path> yourself`. Add `--no-input`/`INVOX_PROMPT_DISABLED`. Wrap errors as `editor "vi" failed: …; set VISUAL/EDITOR`.

**7. [minor] Editor invocation details.** VERIFIED to be safe against filename injection: `-o 'we ird $(touch PWNED) \`id\` ".yaml'` passes the name as one argument and creates no `PWNED`. `eval` is applied only to the editor string, which is intended. Problems: a user's `INVOX_EDITOR` is silently overwritten (`editor.go:130`); with VISUAL=`showargs x` and INVOX_EDITOR=nano, showargs ran. `-l` sources profiles. `SHELL=/bin/false` → opaque `exit status 1`. READ: under fish, nu, or csh's `-lc`, `"$1"` doesn't work. On Windows, `cmd /c "code --wait" path` passes a quoted multi-word editor as a single token. Fix: honor `INVOX_EDITOR` > `VISUAL` > `EDITOR`. Run `/bin/sh -c '<editor> "$@"' sh path` (not `$SHELL -l`), or shell-split with `github.com/google/shlex`.

**8. [major] No confirmation, `--force` or `--dry-run`; some writes clobber silently.** VERIFIED: a second `render` overwrites `./invoice.tex` (exit 0); `build` overwrites the PDF (`copyFile` → `os.WriteFile`, `service.go:1987`). Re-archiving an edited invoice deletes the old archived file (`drafts.go:340`) without saying so. Good: `new`, `archive` and `archive edit` refuse an existing target, and archiving writes a copy then removes the source, so it works across devices. Fix: add `--force` to render/build/email when `-o` names a file that is not a previous invox output. Add `archive --dry-run`. Print the replaced archive path on stderr.

**9. [major] The "atomic" write helper doesn't keep the mode or symlinks; some writes skip it.** Rule: "temp file + rename, keep mode; resolve symlinks". VERIFIED: a `chmod 600 c.yaml` invoice becomes 0644 after `build` (`numbering.go:455` chmods a hard-coded 0644). Running `increment` on `link.yaml → c.yaml` replaced the symlink with a regular file, and c.yaml stayed stale. READ: there is no fsync, and check-then-rename leaves a TOCTOU window in `new`/`archive`. Non-atomic `os.WriteFile` is used for init (`init.go:71`), the config template (`service.go:439`), `.tex` (`service.go:927`) and PDF/assets (`service.go:1987`). Fix: copy the existing mode, `filepath.EvalSymlinks` the target, fsync, and use `O_EXCL`/`os.Link` for create-only paths. Route all writes through the helper.

**10. [minor] YAML rewrite keeps comments but reformats.** VERIFIED: `build` kept the head and trailing comments. It dropped blank lines, re-indented 4→2, and re-flowed a `>-` folded scalar onto one line. Fix: patch only the `status:` scalar's line (the yaml.Node gives `Line`/`Column`), or document the reformat.

**11. [major] A broken config.yaml blocks everything, including recovery.** Rule: "an explicit … path replaces discovery". VERIFIED with `archive: dir: [unclosed`: init, customer/template/archive list, new and validate all exit 1, even `customer list -c <file>`. That happens because `DefaultOptions()` always parses config (`parsing.go:57`). The error is actionable (`…/config.yaml: yaml: line 1: did not find expected…`). `--help`, `help config`, `completion` and `config` still work. `paths: 5` and unknown keys are silently ignored. Fix: resolve flags first and read config lazily. Make `init` independent of config. Warn on unknown or ill-typed keys.

**12. [major] No config-dir override, no env docs, and inconsistent platform paths.** Env vars read (READ, `grep Getenv`): `XDG_CONFIG_HOME`, `XDG_DATA_HOME` (not on macOS), `APPDATA` (Windows data only), `VISUAL`, `EDITOR`, `SHELL`. There is no `INVOX_*` variable and no `--config`. `invox help environment` returns `unknown help topic` (exit 2). Config lives in `~/.config/invox` on every OS (APPDATA is ignored on Windows), but the archive goes to `~/Library/Application Support` on macOS and `%APPDATA%` on Windows (`service.go:983-1010`). `help config` hard-codes `~/.config/invoice-tool` (`help.go:782`). **The failing test**: `TestEditableConfigPathCreatesCommentedTemplate` expects `~/Library/Application Support/invox/invoices` in the template. `archiveDataBaseDir()` switches on `runtime.GOOS`, so on Linux the value is `~/.local/share/invox/invoices`. It would also follow an inherited `XDG_DATA_HOME`, which the test never clears. Fix the test to build `want` from `configTemplatePath(DefaultArchiveDir())` with `XDG_DATA_HOME` set. Product fix: add `INVOX_CONFIG_DIR`/`INVOX_DATA_DIR` and a `help environment` topic. Pick one directory scheme per OS. Add `invox config path`/`list` showing each value's source.

**13. [major] Resolution order works as documented, but the upward search is unbounded, and `init` hides a legacy setup.** VERIFIED order: flag > upward search > `paths.*` > config dir. The upward search walks up to `/`, so a stray `~/customers.yaml` (or `/tmp/customers.yaml`) overrides `paths.customers` from any subdirectory, and no output says which file was used. Legacy: with only `~/.config/invoice-tool`, `customer list` shows `LEG-1` and `config` opens the legacy file. Running `invox init` then creates `~/.config/invox` from the starter files, and the next `customer list` shows `CUST-001 Appsters GmbH`. The legacy customers, config and `archive.dir` are silently hidden. Fix: stop the search at `$HOME` or at a project marker. Have `init` detect the legacy dir and offer to migrate it (or require `--force`).

**14. [minor] Secrets/PII file modes.** VERIFIED: `issuer.yaml` (IBAN/BIC), customers.yaml and archived invoices are created 0644, in 0755 directories. Nothing is logged. On macOS the osascript argv carries the email body, which `ps` can see. Fix: use 0600 files and 0700 directories for config and archive, and keep the existing mode on rewrites.
