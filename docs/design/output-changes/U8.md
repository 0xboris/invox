# Output changes: U8, one YAML decoder

`config.yaml` is decoded by the `store` decoder that reads `customers.yaml`, `issuer.yaml`,
`invoice_defaults.yaml` and the invoices. Its values follow the same rules as theirs, and it gains
their duplicate-key, merge-key and alias checks. Every config problem still prints with the hint
`Run 'invox config' to open and fix the config file.` (or `--config FILE` in it) and exits 1.

No testscript golden, `docs/cli` page or `share/man` page changed: none pins a message below.
`broken_config.txtar` (syntax error) and `config_paths.txtar` (`unknown key "patern" in
numbering`) pass unchanged. The changed messages show in `TestLoadReportsProblemsWithFileAndLine`,
which moved from `internal/config` to `internal/store`.

## Values that are now accepted

A text setting takes any scalar as its text, and `numbering.start` takes an integer written as a
string, as `customers.yaml` already did for `numbering.start`:

| `config.yaml` | Before | Now |
| --- | --- | --- |
| `email.subject: 5` | `config.yaml:2: email.subject: expected a string, got integer 5`, exit 1 | subject `5` |
| `archive.dir: true` | `config.yaml:2: archive.dir: expected a string, got boolean true`, exit 1 | archive directory `true` next to `config.yaml` |
| `numbering.start: "3"` | `config.yaml:2: numbering.start: expected an integer, got string "3"`, exit 1 | start 3 |
| `numbering: {pattern: x, start: "3"}` | `config.yaml:1: expected an integer, got string "3"`, exit 1 | start 3 |
| `defs: &d {dir: x}` and `archive: *d` | `config.yaml:1: unknown key "defs"`, exit 1 | a top-level key whose value defines an anchor holds definitions, as in the support files; archive directory `x` |

## Changed messages

| `config.yaml` | Before | Now |
| --- | --- | --- |
| `numbering.start: 1.9` | `config.yaml:2: numbering.start: expected an integer, got number 1.9` | ``config.yaml:2: numbering.start: expected an integer, got `1.9` `` |
| `numbering.start: x` | `config.yaml:2: numbering.start: expected an integer, got string "x"` | ``config.yaml:2: numbering.start: expected an integer, got `x` `` |
| `numbering.start: ''` | `config.yaml:2: numbering.start: expected an integer, got string ""` | ``config.yaml:2: numbering.start: expected an integer, got `` `` |
| `numbering: {pattern: x, start: 1.9}` | `config.yaml:1: expected an integer, got number 1.9` | ``config.yaml:1: numbering.start: expected an integer, got `1.9` ``: a flow mapping now names the key |
| `- a` (a list, or any non-mapping document) | `config.yaml:1: the top level must be a mapping, got a list` | `config.yaml: root value must be a mapping`, the support files' wording |
| `~` (a null document) | the zero config, exit 0 | `config.yaml: root value must be a mapping`, exit 1. An empty file or one with only comments is still the zero config |
| `paths:` twice | `config.yaml:3: mapping key "paths" already defined at line 1` | `config.yaml:3: duplicate key "paths" (first defined on line 1)` |
| `paths: &p` with `customers: *p` | `config.yaml:1: expected a string, got a mapping` | `config.yaml:2: alias *p refers to a node that contains it` |
| `archive.dir:` an alias that expands past 100,000 nodes | yaml.v3 expanded it; the file failed only on its other problems, such as `config.yaml:1: unknown key "a0"` for each anchor holder | `config.yaml:N: aliases expand to more than 100000 nodes`, naming the outermost alias's line |
| an indented first key, `  paths:` | `config.yaml:2: top-level keys must not be indented; remove the leading whitespace before "paths:"` | `config.yaml:2: top-level keys must not be indented; remove the leading whitespace before "paths"`: the key, not the line |

Unchanged: unknown keys (`unknown key "foo"`, `unknown key "patern" in numbering`), a section
that is not a mapping (`paths must be a mapping, got an integer`), a list or mapping where text
belongs (`email.body: expected a string, got a list`), syntax errors (yaml.v3's text after the
file name), several problems in one file (one line each, in file order), an empty or
comment-only file, and a missing `--config` file.

Changed files: none.
