# Output changes: U3, stop reading Markdown archived invoices

invox no longer reads archived invoices stored as Markdown with YAML front matter (`.md`,
`.markdown`). Every command that walks the archive leaves them out and names them in one
warning on stderr, printed once by the command from the data billing returns. Exit codes,
stdout and `--json` are what they would be without those files. A Markdown file in the
archive that does not open with a `---` line was never read as an invoice and is not named.

The warning, with paths shortened against the working directory as other paths are:

```
warning: 1 Markdown invoice in <archive dir> is no longer read; convert it to .yaml to include it:
  <archive dir>/old.md
```

```
warning: 2 Markdown invoices in <archive dir> are no longer read; convert them to .yaml to include them:
  <archive dir>/a.md
  <archive dir>/sub/b.markdown
```

What a user sees now, with Markdown invoices in the archive:

| Command | Before | Now |
| --- | --- | --- |
| `archive list` | listed the `.md` invoices | leaves them out; prints the warning first. `--json` leaves them out too, with the warning on stderr |
| `new`, `increment` | counted their numbers | ignore them, so the next number can be lower (an archive of `CUST-001-009.yaml` and `CUST-001-015.md` now gives `CUST-001-010`); print the warning before the other lines |
| `new --from-last` | could start from a `.md` invoice | starts from the last `.yaml` one, or fails with `no archived invoice found for customer_id ...` when there is none |
| `validate` | warned when a `.md` invoice had the same number | prints the Markdown warning instead of the duplicate warning |
| `archive add`, `build --archive` | refused an invoice whose number a `.md` invoice had | archive it; print the warning first (also with `--dry-run`) |
| `email FILE.pdf`, when the invoice is looked up by walking the archive | could not match a `.md` file anyway | prints the warning when the walk skipped any |
| `archive edit X.md` | copied it to `X.yaml` with `_invox.archive_replace_path`, and re-archiving replaced the `.md` | exit 1, `error: <archive dir>/X.md is a Markdown invoice, which invox no longer reads; convert it to .yaml` |
| re-archiving a working copy that still has `_invox.archive_replace_path` | replaced (and backed up) that file too | ignores the key: only `archive_path` is replaced, the old file stays and the Markdown warning names it. `validate` of such a working copy fails with `unknown key "archive_replace_path" in _invox` |

Changed files:

- `cmd/invox/testdata/script/archive.txtar`: `archive list` with `legacy.md` in the archive no
  longer lists it (`want-list.tsv` loses the `legacy.md	CUST-MD	2026-03-05	archived` row) and
  prints `want-markdown-warning.txt` on stderr. New step: `archive edit legacy.md` exits 1 with
  `want-edit-markdown.txt`. The script then removes `legacy.md`.

`docs/cli` and `share/man` are unchanged: no help text mentioned Markdown archives.
