# Output changes: U6, error wording and adapter errors

## One wording for an output file that exists or is a directory

`cmdutil.OutputError` words `*billing.OutputExistsError` and `*billing.OutputIsDirError` for
every command that writes a file the user names: `new`, `email`, `render` and `build` (`-o`),
and `archive edit` (its working copy). `email.Mailer` now returns these two errors, and the
LaTeX renderer returns `*billing.OutputIsDirError` for `render` and `build`. Exit codes are
unchanged (1).

| Command | Before | Now |
| --- | --- | --- |
| `invox email inv.yaml -o existing.eml` | `error: existing.eml already exists; pass --force or choose another -o path` | `error: existing.eml already exists; pass --force to replace it or choose a different -o/--output path` |
| `invox email inv.yaml -o dir.eml` (a directory) | `error: dir.eml is a directory; choose another -o path` | `error: dir.eml is a directory; choose a different -o/--output path` |
| `invox render inv.yaml -o dir.tex` (a directory) | `error: rename .invox-2546425484 dir.tex: file exists` (a random temporary name) | `error: dir.tex is a directory; choose a different -o/--output path` |
| `invox build -i inv.yaml -o dir.pdf` (a directory) | tectonic ran, then `error: rename .invox-NNN dir.pdf: file exists` (inferred from the code, not run) | `error: dir.pdf is a directory; choose a different -o/--output path`, before tectonic runs |

`new` and `archive edit` already used these words.

Changed files:

- `cmd/invox/testdata/script/email.txtar`: `want-exists.txt` and `want-dir.txt` take the new
  wording.

## A support file named on the command line that does not exist

`-c/--customers`, `-u/--issuer`, `--defaults` and a `-t/--template` path that name a missing
file now fail with a `*billing.FileNotFoundError` carrying that path, worded like a missing
`--config` file. It stays a runtime error (exit 1, no usage line), like a missing `--config`
file and a missing invoice argument: the flag was well formed, and its help would not fix it.
`customer.txtar` pins exactly that ("Runtime errors": exit 1, no `for usage`). A file the lookup
does not find at all is still the usage error that names the ways to provide it (exit 2).
`customer edit -c new.yaml` still opens the editor on a file that does not exist yet.

| Command | Before | Now |
| --- | --- | --- |
| `invox new CUST-001 -c /nope.yaml` | `error: open /nope.yaml: no such file or directory` | `error: customers file /nope.yaml does not exist` |
| `invox new CUST-001 -u /nope.yaml` | `error: open /nope.yaml: no such file or directory` | `error: issuer file /nope.yaml does not exist` |
| `invox new CUST-001 --defaults /nope.yaml` | `error: open /nope.yaml: no such file or directory` | `error: defaults file /nope.yaml does not exist` |
| `invox render inv.yaml -t /nope.tex` | `error: open /nope.tex: no such file or directory` | `error: template file /nope.tex does not exist` |
| `invox customer list -c /nope.yaml` | `error: open /nope.yaml: no such file or directory` | `error: customers file /nope.yaml does not exist` |

The same holds for every other command with these flags (`validate`, `build`, `email`,
`increment`). Exit code 1 in every row, before and after.

No testscript golden, `docs/cli` or `share/man` page changed. `customer.txtar` matches
`missing\.yaml` and passes unchanged; `TestNamedSupportFileThatDoesNotExist` pins the rows.
