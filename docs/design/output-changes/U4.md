# Output changes: U4, check placeholders and drop the removed names

## Template placeholders

`render` and `build` (and `build --dry-run`, `render --dry-run`) check every `@@NAME@@` token
in the template against the placeholders the renderer fills. An unknown one fails with exit 1,
one line per name in the order they first appear, and nothing is written:

```
error: <template>: @@CUSTOMR_NAME@@: unknown placeholder
```

Before, an unknown name stayed in the `.tex` output as written and the command exited 0.

The four names invox dropped earlier give the same message instead of their own:

| Template has | Before | Now |
| --- | --- | --- |
| `@@VAT_RATE@@`, `@@VAT_AMOUNT@@` | `@@VAT_RATE@@: unsupported placeholder; use @@VAT_SUMMARY_ROWS@@` | `@@VAT_RATE@@: unknown placeholder` |
| `@@ISSUER_CITY_AND_POSTAL_CODE@@` | `...: unsupported placeholder; use @@ISSUER_POSTAL_CODE@@ @@ISSUER_CITY@@` | `@@ISSUER_CITY_AND_POSTAL_CODE@@: unknown placeholder` |
| `@@CUSTOMER_CITY_AND_POSTAL_CODE@@` | `...: unsupported placeholder; use @@CUSTOMER_POSTAL_CODE@@ @@CUSTOMER_CITY@@` | `@@CUSTOMER_CITY_AND_POSTAL_CODE@@: unknown placeholder` |
| the old starter row `VAT (@@VAT_RATE@@\%): & @@VAT_AMOUNT@@\\` on a line of its own | rewritten to `@@VAT_SUMMARY_ROWS@@` while rendering, exit 0 | `@@VAT_RATE@@: unknown placeholder` and `@@VAT_AMOUNT@@: unknown placeholder`, exit 1 |

Changed files:

- `cmd/invox/testdata/script/render.txtar`: new step, `render` with `misspelt.tex`
  (`@@CUSTOMR_NAME@@`) exits 1 with `want-misspelt.txt` and writes no `.tex`.
- `cmd/invox/testdata/script/help.txtar`: the `invox template` page says "An unknown
  placeholder fails render and build; the error names it." instead of "Unknown placeholders are
  left unchanged in the rendered TeX.", and loses the line "@@VAT_RATE@@ and @@VAT_AMOUNT@@ are
  unsupported; use @@VAT_SUMMARY_ROWS@@."
- `docs/cli/invox_template.md` and `share/man/man1/invox-template.1`: the same two help lines,
  regenerated with `make docs`.

## Email placeholders

`email` checks every `{name}` token (lower-case letters and `_`) in the subject template and the
body template, whether they come from `email.subject`, `email.body` or `--subject`, against the
placeholders it fills. An unknown one fails with exit 1 before anything is drafted or opened, one
line per name, subject first:

```
error: email.subject: unknown placeholder {invoice_numbr}
email.body: unknown placeholder {customr_name}
```

Before, the token stayed in the draft as written and the command exited 0. A body that quotes
such a token literally, as in `{note}`, now fails too.

The check runs before the attachment and output checks, so `email invoice.yaml -o d.eml
--subject '{nope}'` without `invoice.pdf`, or with an existing `d.eml`, reports the placeholder
instead of the missing PDF or the existing file (`TestPortOrder` cases
`email-missing-pdf-and-bad-subject` and `email-dry-run-output-exists-bad-subject`).

The starter `config.yaml` is unchanged: its placeholder list now comes from the same table.

Changed files:

- `cmd/invox/testdata/script/email.txtar`: new step, `email --subject 'Invoice {invoice_numbr}'`
  exits 1 with `want-unknown-placeholder.txt` and writes no draft.
- `cmd/invox/testdata/script/help.txtar`: the `invox config` page gains the line "Any other
  {name} in email.subject, email.body or --subject fails the email command." under "email
  template placeholders".
- `docs/cli/invox_config.md` and `share/man/man1/invox-config.1`: the same line, regenerated with
  `make docs`.

## Removed YAML keys

`line_items`, `invoice.period_label` and `invoice.vat_rate_percent` are unknown keys like any
other. Where a strict decode reads them (`validate`, `render`, `build`, `email`, and `new` from
`invoice_defaults.yaml`), each gives `file:line: unknown key "line_items"` (or `unknown key
"period_label" in invoice`, `unknown key "vat_rate_percent" in invoice`) and the existing hint
`Remove the unknown keys or fix their spelling; 'invox help defaults' lists the supported
fields.`, exit 1 as before, instead of `file:line: line_items: unsupported key; use positions`.
`archive add` is unchanged: it archived an invoice with these keys before and still does, as it
does with any unknown key.

Archived invoices keep unknown keys, as they already did for any other key:

| Command | Before | Now |
| --- | --- | --- |
| `new --from-last` from an archived invoice with these keys | exit 1, `unsupported key; use ...` per key | exit 0; the new invoice keeps the keys as written, and `validate`, `render`, `build`, `email` of it fail with `unknown key` and the hint |
| `archive edit` of such an invoice | exit 1, `unsupported key; use ...` per key | exit 0; the working copy keeps the keys, `validate` of it fails with `unknown key` and the hint, and re-archiving it succeeds and keeps them |

Changed files:

- `cmd/invox/testdata/script/validate_problems.txtar`: `want-unknown.txt` reports
  `unknown.yaml:2: unknown key "line_items"` and `unknown.yaml:8: unknown key "vat_rate_percent"
  in invoice` instead of the two `unsupported key; use ...` lines.
- `cmd/invox/testdata/script/help.txtar`: `invox help defaults` loses the "Unsupported legacy
  keys" group (`line_items`, `invoice.period_label`, `invoice.vat_rate_percent`).
- `docs/cli/invox_help_defaults.md` and `share/man/man1/invox-help-defaults.1`: the same group
  removed, regenerated with `make docs`.
